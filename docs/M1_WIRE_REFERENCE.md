## Message envelope

`protocol/src/main/scala/org/alephium/protocol/message/Message.scala` composes a message as:

```text
network_magic
|| checksum(data)
|| data_length
|| data

where:

data = header || payload
payload = payload_code || payload_body
```

`MessageSerde.scala` verifies magic bytes, extracts a four-byte length field using `Bytes.toIntUnsafe`, rejects negative length, extracts exactly that many bytes, verifies checksum, then deserializes header and payload. `Message.deserialize` rejects redundant trailing bytes.

**Status:** `SOURCE CONFIRMED`, `VECTOR REQUIRED`.

## Byte order used by fixed-width values

`util/.../Bytes.scala` encodes `Int` and `Long` in big-endian order.

Examples from source semantics:

```text
Int:  [value >> 24, value >> 16, value >> 8, value]
Long: [value >> 56, ..., value]
```

This fixed-width encoding is used for the outer frame length and timestamp. Do not assume it is used for every integer: regular `intSerde` uses Alephium compact signed integer encoding.

**Status:** `SOURCE CONFIRMED`, `VECTOR REQUIRED`.

## Network magic

`protocol/.../config/NetworkConfig.scala` defines:

```text
magic_bytes = Bytes.from(
  Hash.hash("alephium-<network-id>").toRandomIntUnsafe
)
```

`Hash` is the protocol Blake2b type at this baseline. The selected M1 network ID and resulting four canonical bytes must be emitted by the Scala oracle and recorded in the fixture manifest.

**Status:** `SOURCE CONFIRMED`, `VECTOR REQUIRED`.

## Wire header and version

Sources:

```text
protocol/src/main/scala/org/alephium/protocol/WireVersion.scala
protocol/src/main/scala/org/alephium/protocol/package.scala
protocol/src/main/scala/org/alephium/protocol/message/Header.scala
```

The current version is created from bytes:

```text
00 01 00 00
```

interpreted as a big-endian signed Int. Header validation accepts exactly `currentWireVersion` at the pinned baseline.

Header serialization goes through `WireVersion.serde`, whose underlying `intSerde` uses compact signed integer encoding. Therefore the source value and its wire bytes are distinct concerns; use the Scala vector rather than encoding the raw four bytes directly.

**Status:** `SOURCE CONFIRMED`, `VECTOR REQUIRED`.

## Integer and collection codec ownership

`serde/.../Serde.scala` confirms:

```text
Int       -> CompactInteger.Signed
Long      -> CompactInteger.Signed
U32       -> CompactInteger.Unsigned
ByteString-> compact-signed length || raw bytes
AVector<T>-> compact-signed element count || encoded elements
TimeStamp -> fixed 8-byte big-endian milliseconds
```

The exact compact integer bit layout belongs to `serde/.../CompactInteger.scala` and must be locked with boundary vectors before Rust implementation.

The official collection decoder rejects negative sizes and sizes larger than available input before allocating an array. Rust must additionally preserve explicit configured limits for network-facing buffers.

**Status:** `SOURCE CONFIRMED`; compact boundary table is `UNRESOLVED` until M1-001 vector generation.

## InterBrokerInfo

Source:

```text

```

Product order:

```text
clique_id

```

Hash input is the canonical serialized `InterBrokerInfo`; the result uses protocol `Hash` (Blake2b at this baseline).

Validation requires:

```text
0 <= broker_id < broker_num
broker_num <= configured_groups
configured_groups % broker_num == 0
```

## Client ID parsing

Sources:

```text
protocol/src/main/scala/org/alephium/protocol/model/ReleaseVersion.scala
protocol/src/main/scala/org/alephium/protocol/message/P2PVersion.scala
flow/src/main/scala/org/alephium/flow/network/broker/BrokerHandler.scala
```

Release parsing reads the second slash-separated segment and applies network/hard-fork minimum-version checks.

P2P parsing accepts:

```text
three segments                    -> P2P v1
four segments ending in p2p-v1   -> P2P v1
four segments ending in p2p-v2   -> P2P v2
other layouts                     -> invalid
```

The Rust node must identify itself honestly and must not advertise v2 before v2 behavior is implemented.

**Status:** `SOURCE CONFIRMED`; final Rust client ID for M1 remains `UNRESOLVED` until the local test network and compatible release field are fixed.

## Remaining M1-001 work

Do not begin the Rust codec implementation until these are completed:

1. extract the compact signed/unsigned integer boundary table;
2. locate and inspect exact SecP256K1 key/signature byte types;
3. select a deterministic local test network/configuration;
4. generate canonical network magic;
5. generate canonical Header/Hello/Ping/Pong payload and full-frame hex;
6. generate valid and invalid signature fixtures in both directions;
7. capture official errors/consumed-byte behavior for malformed fixtures;
8. commit a reproducible Scala vector generator and manifest.
