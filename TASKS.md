## M1 — Official P2P handshake and Ping/Pong

Read `docs/M1_P2P_INTEROP.md` and `docs/M1_WIRE_REFERENCE.md` before starting.

### M1-001 — Freeze official M1 behavior and create Scala-derived vectors

**Status:** `OPEN`

**Upstream minimum:**

- `protocol/.../message/Message.scala`;
- `protocol/.../message/MessageSerde.scala`;
- `protocol/.../message/Header.scala`;
- `protocol/.../message/Payload.scala`;
- `protocol/.../message/P2PVersion.scala`;
- `protocol/.../message/RequestId.scala`;
- `protocol/.../model/ReleaseVersion.scala`;
- `protocol/.../model/BrokerInfo.scala`;
- `protocol/.../model/CliqueInfo.scala`;
- `protocol/.../model/CliqueId.scala`;
- relevant protocol and flow tests listed in `docs/UPSTREAM_MAPPING.md`.

**Deliverables:**

- exact frame layout and byte order document;
- exact checksum algorithm/source path;
- exact integer/string/vector encodings used by M1;
- canonical valid `Hello`, `Ping`, and `Pong` byte vectors generated by Scala;
- malformed/truncated vectors;
- vector provenance manifest.

**Acceptance:** vectors can be regenerated from the pinned Scala source; no expected bytes are based only on Rust round trips.

### M1-002 — Implement bounded Alephium binary codec primitives required by M1

**Status:** `OPEN`

**Dependency:** M1-001.

**Scope:** only integer, fixed-byte, string, vector/product primitives actually required by the M1 structures.

**Acceptance:** all M1 primitive vectors pass; malformed and allocation-limit cases fail without panic.

### M1-003 — Implement official message envelope codec

**Status:** `OPEN`

**Dependency:** M1-002.

**Scope:** network magic, checksum, length, message header, payload code, incremental decode state.

**Acceptance:** byte-for-byte parity with Scala vectors; supports fragmented TCP reads and multiple frames in one read buffer; rejects wrong magic/checksum/length according to upstream behavior.

### M1-004 — Implement M1 protocol models

**Status:** `OPEN`

**Dependency:** M1-002.

**Scope:** timestamp, request ID, wire header/version, P2P version, release/client ID parsing, broker/clique structures required by `Hello`, `Ping`, and `Pong`.

**Acceptance:** canonical encode/decode parity and upstream validation vectors pass.

### M1-005 — Implement official handshake cryptography and identity persistence

**Status:** `OPEN`

**Dependency:** M1-001, M1-004.

**Scope:** only official algorithms and key formats required by handshake; persistent identity file with atomic creation and restrictive permissions where supported.

**Acceptance:** Rust verifies Scala signatures and Scala verifies Rust-produced `Hello` signatures.

### M1-006 — Implement `Hello`, `Ping`, and `Pong`

**Status:** `OPEN`

**Dependency:** M1-003, M1-004, M1-005.

**Acceptance:** payload bytes match Scala; invalid signature/timestamp/broker info are handled consistently; client ID is parser-compatible and honestly identifies the Rust implementation.

### M1-007 — Implement TCP connection and handshake state machine

**Status:** `OPEN`

**Dependency:** M1-003, M1-006, M0-004.

**State model:**

```text
Disconnected -> Connecting -> TCP Connected -> Hello Sent
-> Established -> Closing/Disconnected
```

**Acceptance:** timeouts, EOF, malformed frame, invalid `Hello`, and clean shutdown do not panic or leak an unbounded task/queue.

### M1-008 — Implement Ping/Pong liveness

**Status:** `OPEN`

**Dependency:** M1-007.

**Acceptance:** request IDs are correlated according to official semantics; timeout behavior is documented and tested.

### M1-009 — Official Scala interoperability gate

**Status:** `OPEN`

**Dependency:** M1-008.

**Required evidence:**

- pinned official node logs showing Rust peer accepted;
- Rust logs showing valid official `Hello` received;
- successful Ping/Pong in both required directions;
- connection remains established for at least the duration defined in the M1 runbook;
- no adapter/proxy translating messages;
- exact commands/configs committed without secrets.

### M1 exit gate

M1 is complete only when M1-001 through M1-009 are `DONE` and the evidence is reproducible.
